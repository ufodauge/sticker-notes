# 瓶モードの発展アイデア

2026-11-24 時点の思いつき集。実装の約束ではなく、選ぶための材料。現状は `docs/jar-spike.md` と README の「瓶モード」を参照(暗い部屋、上からの光、形に沿ったアクリルブロック、合成した音)。

評価の軸は 4 つ: 驚き(見せたくなるか)/ 作る手間 / 実機でのリスク / 保守コスト。

## 実装状況(2026-11-25)

決定: リリース前なので、楽な順で 3D(WebGL、three.js と rapier3d)に進める。机は見栄えのよい斜め上からの視点、取り出したブロックは机に残す。
- 済み: 机の上の瓶(斜め上のカメラ、スポットライト、影)、押し出したアクリルブロック、ブロックを持ち上げて机に出す、瓶を滑らせる・倒す、「瓶を立て直す」、傾きで重力(カメラは固定)、音、選択、WebGL2 がなければ 2D
- 次: 瓶の屈折と動的なコースティクス、カメラの回転(スマホを回すと側面が見える)、ふた、ライトの操作、ガチャとふるい分け、裏面の QR

## 1. 机と瓶(世界を広げる)

| アイデア | 中身 | 驚き | 手間 | 備考 |
| --- | --- | --- | --- | --- |
| 机の上に置く | 瓶は机の天板に載っている。ブロックを瓶から取り出して机に並べる・積む・立てる。机は瓶の外の広い床になる | ★★★ | 中 | 今の物理は「瓶の中だけ」。壁を瓶の内側の輪郭から、机の天板と瓶の剛体に変える |
| 瓶を倒せる | 瓶自体を剛体にする。ドラッグで押す・傾ける・倒す。倒れると口からブロックが転がり出る。起こせば元に戻る | ★★★ | 中〜大 | ガラスの壁を複合の剛体に。ブロックが机の上に散らばる。机の端から落ちたものは戻す |
| ふた | コルクのふたを開け閉めできる。閉じた瓶を振ると中で鳴る(音を丸くする) | ★★ | 小 | 開けているときだけ中身が出られる |
| 取り出して飾る | ブロックを机の台座に立てて飾る(アクリルスタンド)。並べて写真を撮れる | ★★★ | 小〜中 | 「見せたくなる」に直結 |
| 動的な影と屈折 | ブロックが机に落とす影、瓶が机に作る光の模様(コースティクス)が、動きに合わせて変わる | ★★ | 大 | 今の canvas 2D では重い。WebGL が前提(3 節) |

## 2. 光と雰囲気

- **ライトを操作できる**: 光源をドラッグで動かす。スマホなら傾きで光が動く。ブロックの縁のツヤが光に追従する。
- **スイッチ**: 暗闇からの点灯(ランプのスイッチ音つき)。起動時の見せ場にもなる。
- **光の種類**: 白熱灯、ろうそくのゆらぎ、ネオン。時刻や季節で変える案もある。
- **環境音**: 部屋の低い空調音のようなもの。ブロックの音に深みが出る。小さな音量で、切れるようにする。
- 気をつける点: 動きと音は、公共の場では控えめにできること(今の音ボタン、動きを減らす設定で守る)。

## 3. 3D

選択肢は 3 段階。上ほど軽く、下ほど新しいことができる。

1. **視差(2.5D)**: 瓶の奥の層、中の層、手前のガラスの層を、端末の傾きに合わせて少しずつずらす。瓶が立体に見える。今の canvas のままで足せる。物理は変わらない。
2. **2D の物理 + 3D の描画**: 物理は今の 2D のまま、ブロックを薄い板として 3D で描く(WebGL)。瓶は円筒として描き、カメラを回すと、ブロックの厚みと瓶の側面が見える。奥行き方向には、ブロックごとに少しずらした層を割り当てる。見た目の効果が大きく、物理の不確実さが小さい。
3. **本物の 3D 物理**: three.js と物理エンジンで、ブロックを立体として扱う。瓶を倒すと、ブロックが奥行きの方向にも散らばる。バンドルが大きく(3D の物理は WASM)、スマホでの負荷が高い。

スマホを立てて左右に回すと側面が見える、という使い方:
- 端末の向き(`deviceorientation` の yaw)を、カメラの周回に割り当てる。iOS は許可が要り、方位の基準が機種ごとにずれるので、「起動時の向きを 0 とする相対回転」にする。
- 傾き(pitch)は、今の傾きによる重力の向きに使い続けるか、カメラに使うかを選ぶ必要がある。両方は同時に使いにくい。切り替えスイッチか、2 本指の操作で分ける。
- デスクトップはドラッグで視点を回す。モーション軽減では固定視点。

面白い副産物: アクリルブロックを**裏返すと背面に QR が彫ってある**。3D で回して見せれば、そのまま交換に使える。

## 4. ギミック

| アイデア | 中身 | 手間 |
| --- | --- | --- |
| ガチャ | 瓶の下のレバーを回すと、ブロックが 1 個出る。「今日の 1 枚」や、交換する 1 枚のおみくじに使う | 小〜中 |
| ふるい分け | 振ると、SNS の種類や色で分かれて沈む(重さや大きさを変える)。コレクションの眺めかたになる | 小 |
| 磁石 | 指を近づけるとブロックが寄る。ゆっくり集めて並べる遊び | 小 |
| 水とゲル | 瓶に液体を入れると、ブロックがゆっくり沈む。泡と粘度。スノードーム風の季節演出も作れる | 中 |
| 積み上げ | 机の上にどれだけ高く積めるか。倒れたら終わり。軽い遊びとして置く | 小 |
| 瓶の動画 | 振る様子を短い動画(WebM)で書き出す。SNS に載せやすい。`canvas.captureStream()` で、重ねた層の合成が要る | 中 |

## 5. 技術メモ

- **描画の土台**: 今は canvas 2D で、層を重ねている。屈折、動的な影、液体を入れるなら WebGL(PixiJS か自前の薄いラッパ)に移すのが前提。移行は 1 回で済ませたい。
- **物理**: matter-js は複合形状で重い。机と倒せる瓶を足すと、剛体が増えて負荷が上がる。ブロックの複合形状を減らす、遠くのブロックは眠らせる、といった調整が必要。planck への差し替えも候補。
- **品質の段階**: `core/jar-quality.ts` の仕組みは使い続ける。机と瓶の追加後は、「動くものを減らす」に、影と反射を切る段階を足す。
- **未検証のまま残っている実機の項目**(`docs/progress.md`): 低価格スマホでの 40〜120 個、iOS の傾きの許可、振動、音の聞こえ方、サイレントスイッチ。ここを先に確かめないと、次の機能の重さを見積もれない。

## 6. 提案する順序

1. **机と倒せる瓶**(1 節): 見た目と遊びの変化が最も大きく、物理だけで済む。ふたと取り出して飾るを同時に入れる。
2. **光の操作と動的な影**(2 節): 机ができた後に、ライトが意味を持つ。
3. **ギミック**(4 節)から、ガチャとふるい分けを先に。小さく、コレクションの意味が出る。
4. **視差**(3 節の 1)でスマホの傾きに応える。
5. **2D の物理 + 3D の描画**(3 節の 2)。WebGL への移行とセットで、裏面の QR もここで作る。
6. 本物の 3D 物理は、上の結果を見てから決める。

## 7. 決めたいこと

- 机を、横から見た断面(今の画面の延長)にするか、斜め上から見た 3D にするか。前者は 1 節だけで完結し、後者は 3 節とセットになる。
- 机の上のブロックの扱い: 瓶から出したブロックは、そのまま残すか、閉じると瓶に戻るか。
- 3D を目指す場合、WebGL への移行を先にやるか、2D のまま机と瓶まで進めるか。
