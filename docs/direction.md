## A を URL で広がる形に練る(たたき台)

- 交換は対面の QR だけでなく URL でもよい。URL を共有するとお得なことがあると広がりやすい
- 循環の案: 自分の URL を送る → 開いた人の出会い帳の最初のページが「誘ってくれた人」になる → その人が自分のシールを作って返す → こちらの出会い帳に相手のページができる
  - 送る側の得: 返事が来るとページが増える(サーバーなしでも、返事の URL が届けば分かる)。会った人数で素材が増える(いまの仕組みを、広げる理由として使える)
  - 開く側の得: 最初から本物の一ページがある(見本や作り物の友だちが要らない)
  - 一人で始める人: 空の帳面と「最初のページは、最初に会った人」。自分のシールを作って、URL か QR で渡すところまで
- 決めること

  - SNS に URL を貼って大勢に配るのを、出会いとして数えるか

## SNS に URL を投げる場合(2026-11-28)

- 今の形(ポケット・机・シール帳)は悪くないので、このままでもよい(オーナー)
- 一対一の交換(対面の QR、直接送る URL)と、SNS で大勢に配るのとでは広がり方が違う。配った側に見返りが来ないのはつらい
- 見返りの道は SNS そのものに任せられる: シールには配った人の SNS ID が入っている。受け取った人がお返しを作ると、その URL を配った人への返信(@ID 付き)として SNS に出せるようにすれば、配った人に届く(サーバーなしで往復できる)
- 数え方の案: 往復した相手だけを「N人目」に数える(配っただけ・受け取っただけは数えない)。人数で開く素材も往復の数で決まるので、配るだけでは増えない。返事をする理由にもなる

## 薄いサーバーを置くなら(2026-11-28)

- 見返りを確実に届けるなら、薄いサーバーを置くのが結局まるい(オーナー)
- 何を届けたいかで形が変わる
  - その場の交換(対面): 二人が同時にいるので、WebRTC のシグナリングだけで足りる。QR は「つなぐ合図」になり、シールは端末どうしで直接渡る
  - SNS で配る(非同期): 相手が後で開くので、同時接続のシグナリングでは届かない。小さな郵便受け(預けて、後で取りに来る)が要る
- 「シールは端末の中だけ」という約束との関係: 送るのは中身でなく合図だけ(どのシールが、何回貼られたか)にすれば、約束をほぼ崩さずに済む

## お返しは本当に嬉しいか(2026-11-28)

- お返しは返さないといけない気持ち(返報の負担)を生む。返事を迫られるのが重い人もいる
- 負担のない見返りの案: 「あなたのシールが、だれかの帳面に貼られた」とだけ届く。相手は何もしなくてよく、貼った行為がそのまま届く。お返しは、したい人だけがする
- 決めること: 届けたいのは「お返し(物)」か「貼られた(合図)」か。合図だけなら郵便受けは数を数えるだけで済む
