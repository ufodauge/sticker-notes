# 3D の机のモデルとテクスチャ(デザイナー向け)

3D の机(`?room`)の物は、ファイルがあればファイルで、なければコードで描いた形で出る。ファイルを置いて `public/room/manifest.json` に書けば、その物だけ差し替わる。読み込みはあとから: 場面はすぐコードの形で出て、ファイルが届いたところで入れ替わる。ファイルがない・壊れているときはコードの形のまま(コンソールに警告が 1 行出るだけ)。

## 決まりごと

- 単位: 1 = 1 m のつもり。机の高さは 0.75。ただし机の上の物は見やすいよう実物より大きめなので、大きさは下の表に合わせる
- 軸: y が上、手前(見ている人の側)が +z、右が +x。窓は奥(-z)
- 原点: 物は自分の原点で置かれる。机の上の物は「底の真ん中」が原点(机の面 y = 0.75 にそのまま載る)
- 形式: モデルは glTF。1 ファイルにまとまる `.glb` がよい(`.gltf` も読める)。マテリアルは glTF の標準(メタリック・ラフネス)。ライトとカメラは入れない
- 影: 読み込むとすべてのメッシュが影を落とし、影を受ける(設定はいらない)
- テクスチャ: `.png` / `.jpg` / `.webp`、色は sRGB。512 か 1024 の正方形。繰り返して貼るので継ぎ目なしに作る。絵がそのまま色になる(コードの色は重ならない)
- 重さ: ファイルはアプリと一緒に配られる。1 つ数百 KB まで(テストは 2 MB で止める)

## ファイルの足し方

1. ファイルを `public/room/` に置く(下にフォルダを作ってもよい)
2. `public/room/manifest.json` の `files` に「名前: ファイル」を書く

```json
{
  "files": {
    "plant": "plant.glb",
    "desk-wood": "textures/desk-wood.webp"
  }
}
```

- 名前は上の表のものだけ。表にない名前や、種類に合わない拡張子(モデルに `.png` など)は無視され、コンソールに理由が出る
- `public/room/` に置いたファイルはすべて manifest に書く(書き忘れはテストで分かる)
- 見本: `plant.glb` はコードから作った見本(`vp run gen:room` で `scripts/gen-room-assets.ts` が書き出す)

## 見方

- `vp dev` で開き、アドレスに `?room` を付ける(例 `http://localhost:5173/?room`)
- 読み込めたものは、canvas 要素の `data-room-assets` に名前が並ぶ(ブラウザの開発ツールで見られる)。読み込めなかったときはコンソールに警告
- ファイルを差し替えたら再読み込み
