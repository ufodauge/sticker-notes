## 瓶モード

- 切り替えと中身の選択は設定(`view`、`jar`)に保存し、起動時に描画の前に読む(Suspense の `use`)ので、保存した表示が最初の描画から出る。`jar` は `{ kind: "auto", seed }` または `{ kind: "manual", ids }`(valibot、`core/jar-selection.ts`)
- 中身は純粋関数 `pickJarIds`: ランダムは種と ID だけで決まる順位の上位 40 枚(`JAR_DEFAULT_COUNT`)、固定は選んだ順の最大 120 枚(`JAR_MAX_COUNT`)。削除したステッカーは、固定では黙って外れる(保存した ID は書き換えない。元に戻せば瓶にも戻る)。新しいステッカーを強制的に入れることはしない(固定では入らない。ランダムでは他と同じ抽選の対象で、40 枚以下なら全部入る)。ランダムでは順位が各ステッカーごとに独立なので、1 枚の増減で瓶が変わるのは高々 1 ブロック
- 瓶のコードは別チャンク(matter-js を含む)。シール帳の表示中は読み込まれない(E2E で確認。オフライン用にサービスワーカーは先に取得する)
- 品質の段階(`core/jar-quality.ts`): 0 = 60Hz・dpr 上限 2、1 = 30Hz、2 = さらに dpr 1、3 = さらに動かすブロックを 80 枚までにして残りは静止した山。1 フレームの仕事量の移動平均が 10ms を超えたら 1 段下げ、3ms 未満が 240 フレーム続いたら 1 段戻す(戻した直後にまた下がったら待ち時間を倍に)。非表示のフレームは数えない
- テスト用の計測口(`window.__jarProbe`)は、ビルド時に `VITE_JAR_PROBE` を付けたとき(E2E のビルド)だけ入る。通常のビルドには含まれない
- 実測(Playwright、ヘッドレス Chromium、デスクトップ、Pixel 7 エミュレーション。**スマホの数値ではない**)。「振る」を押してから静止するまでの、物理 + 描画の 1 回あたりの平均 / 最悪(ms)と、処理した回数:

| 枚数 | 段階 0 | 段階 1 | 段階 2 | 段階 3 |
| --- | --- | --- | --- | --- |
| 20 | 0.18 / 0.4(246 回) | 0.21 / 0.5(110 回) | 0.22 / 2.2(138 回) | 0.20 / 0.4(139 回) |
| 40(既定) | 0.34 / 0.6(200 回) | 0.35 / 0.6(91 回) | 0.37 / 1.9(96 回) | 0.31 / 0.6(133 回) |
| 100 | 0.70 / 1.4(162 回) | 0.69 / 1.4(103 回) | 0.74 / 1.7(96 回) | 0.68 / 1.0(78 回、20 枚を静止) |
| 300(負荷試験) | 2.20 / 5.7(144 回) | 2.50 / 5.7(83 回) | 2.78 / 5.2(76 回) | 1.32 / 1.9(72 回、220 枚を静止) |

  1 回あたりの仕事量は段階 1 以降も大きくは変わらず、1 秒あたりの回数が半分になる(30Hz)ことで負荷が下がる。段階 3 だけは 1 回あたりも下がる。このヘッドレス環境では dpr の差はほとんど出ない。300 枚は `JAR_PERF=1` の負荷試験で、アプリの通常の使い方(最大 120 枚)の外
- 実機で確認が残るもの: 低価格 Android と iPhone での 40 枚・120 枚の操作感、iOS の傾きの許可の流れ、振動(Android Chrome)、WebKit(iPhone)での性能、ダークテーマの実機での見た目

## 網点(ディザ)

- 作成ダイアログに、写真だけで使える「網点でなめらかに」のトグルを足した(初期はオフ、画像を開き直すとオフに戻る。クロップやパレットを変えても保持)
- 手法は Bayer 4x4 の整列ディザ。OKLab で最も近い 2 色の間のどこにあるかを閾値と比べて 2 色から選ぶので、パレット色そのものの平坦な面は平坦なまま、グラデーションは 2 色の比率で再現される(誤差拡散は偏ったパレットで崩れたため不採用)
- パレットの自動順位は網点なしの誤差のまま。ペイロードの形式は変わらず、ドット絵の取り込みと少色画像の 1 対 1 対応には使わない。実機で見た目の好みを確認する

## 自動テスト

- `vp run verify`: フォーマット、lint、`tsc --runExternalCode`、React Compiler の最適化漏れの検査、単体テスト 365 件
- `vp run test:e2e`: Playwright(Chromium と WebKit)104 件(瓶の 13 件 x 2 ブラウザを含む。性能測定の 4 件は `JAR_PERF=1` のときだけ)
  - リンクを開く → 即貼り付け → 元に戻す、作成(sample.png を含む) → QR をスクリーンショットから jsQR で復号して一致、ドラッグの保存、捨てる → 元に戻す、ページの自動追加、バックアップの書き出しと別ブラウザへの読み込み、A4 1ページの PDF
  - `SCREENS=1` で全画面のスクリーンショット(ライト・ダーク、幅 320px)を `test-results/screens/` に出す

## 規模の目安(e2e/scale.spec.ts、デスクトップ)

ステッカー 300 枚、1 ページに 60 枚を貼った状態。

| 項目 | Chromium | WebKit(Playwright の Windows 版) |
| --- | --- | --- |
| バックアップ読み込み | 約 0.1 秒 | 約 6 秒(ほぼ IndexedDB への 300 件の書き込み) |
| ページ表示 | 約 0.2〜0.3 秒 | 約 0.2 秒 |
| 一覧表示 | 約 0.3〜0.5 秒 | 約 0.3 秒 |
| ドラッグ中の最長フレーム間隔 | 70〜150ms | 約 17ms |

WebKit の読み込みの遅さは Windows 版 WebKit 固有の可能性がある。iPhone の Safari で測って、遅ければ分割書き込みと進捗表示を入れる。

## 実装中に直した不具合

- 保存中に次のステッカーのリンクを開くと、前の保存が新しいリンクの `#` を消していた(回帰テストあり)
- Playwright の WebKit で `createImageBitmap` が画像を読めなかった。`<img>` での読み込みにフォールバックする

## パレット評価

- 自動選択の基準は、3x3 のボックスぼかし(OKLab、端はクランプ、透明画素は平均にも誤差にも入れない)をかけた元画像と量子化結果の二乗誤差の和。1 対 1 対応の少色画像は従来どおり
- 単色系(Grayscale / Sepia / Matcha / Indigo / Crimson)は `kind: "filter"` で、自動選択の対象外。作成ダイアログでは自然なパレットの下に区切って並べ、手動で選べる(ドット絵が完全一致するときは従来どおり選ばれる)
- 個人写真 77 枚: 単色系の自動選択は 66% から 0%、自然なパレット 27 種のうち一度も選ばれないものは 11 種
- `node scripts/palette-eval.ts <写真フォルダ> <出力フォルダ>` で plain / blur3-all / app(アプリと同じ `rankPalettes`)を比べる。写真と出力はコミットしない

## パレットの入れ替え(P6)

- 凍結の方針を変更: 公開(告知)前は中身を変えてよい(AGENTS.md、plan.md、palette-data.ts 冒頭を更新)。公開後は ID ごとに凍結
- 一度も選ばれず、フィルターとしての価値も薄い 9 種(Macintosh II、Neon、Sunset、Candy、Twilight、Rainbow Light、Rainbow Vivid、Night City、Desert)と、近い茶系の Portrait を、自作の 10 種に置き換えた: Skin Tones(10)、Overcast(7)、Mist(12)、Daylight(15)、Clear Sky(16)、Stage Light(20)、Lamplight(21)、Everyday(25)、Snapshot(26)、Night(30)
- 色は学習用の写真(77 枚のうち 52 枚)の OKLab k-means で出し、手で調整(各パレットで最小色間距離 0.03 超、暗色と白に近い色を含む)。写真と派生画像はコミットしていない。いずれも `source: "self"`。M0 の「公開パレットのライセンス確認」の対象は、残った Lospec 由来の 9 種だけになる
- 茶系は Sepia(フィルター)、Fire、Autumn、Bakery に整理(最近接距離 0.055 以上)
- 残した古典系: PICO-8、CGA、Commodore 64(ID 0 はテストが使う)
- 数値(自動選択と同じ、ぼかし後の平均誤差。評価用は 3 つに 1 つの 25 枚): 入れ替え前 学習 1.274 / 評価 1.261 → 後 学習 0.953 / 評価 0.797。全 77 枚で 1.270 → 0.902
- 一度も選ばれない自然なパレットは 11 種のまま(PICO-8、Sweetie 16、Endesga 16、Arne 16、Commodore 64、CGA、Pastel、Forest、Ocean、Sakura、Mint Cherry)。ドット絵向けと好みの色味で、写真向けではない。単色系の自動選択は 0%
- 見た目: 夜景は紺や茶の塊が減った。ポートレートの肌色、屋外の青空と緑は改善。曇りの日と白い看板は、Overcast が 27% を占め、暖色の被写体(菓子、猫)が青灰色に寄るのが残る
