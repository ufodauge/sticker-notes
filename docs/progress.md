## 自動テスト

- `vp run verify`: フォーマット、lint、`tsc --runExternalCode`、React Compiler の最適化漏れの検査、単体テスト 134 件
- `vp run test:e2e`: Playwright(Chromium と WebKit)36 件
  - リンクを開く → 即貼り付け → 元に戻す、作成(sample.png を含む) → QR をスクリーンショットから jsQR で復号して一致、ドラッグの保存、捨てる → 元に戻す、ページの自動追加、バックアップの書き出しと別ブラウザへの読み込み、A4 1ページの PDF
  - `SCREENS=1` で全画面のスクリーンショット(ライト・ダーク、幅 320px)を `test-results/screens/` に出す

## 規模の目安(e2e/scale.spec.ts、デスクトップ)

ステッカー 300 枚、1 ページに 60 枚を貼った状態。

| 項目 | Chromium | WebKit(Playwright の Windows 版) |
| --- | --- | --- |
| バックアップ読み込み | 約 0.1 秒 | 約 6 秒(ほぼ IndexedDB への 300 件の書き込み) |
| ページ表示 | 約 0.2〜0.3 秒 | 約 0.2 秒 |
| 一覧表示 | 約 0.3〜0.5 秒 | 約 0.3 秒 |
| ドラッグ中の最長フレーム間隔 | 70〜150ms | 約 17ms |

WebKit の読み込みの遅さは Windows 版 WebKit 固有の可能性がある。iPhone の Safari で測って、遅ければ分割書き込みと進捗表示を入れる。

## 実装中に直した不具合

- 保存中に次のステッカーのリンクを開くと、前の保存が新しいリンクの `#` を消していた(回帰テストあり)
- Playwright の WebKit で `createImageBitmap` が画像を読めなかった。`<img>` での読み込みにフォールバックする
