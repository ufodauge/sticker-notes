# これからの計画(魅力向上)

元資料: `.vscode/sticker-notes 魅力向上計画.md`(2026-11-24)。ここはそこから「何を、誰が、どの順で、何をもって完了とするか」だけを抜き出した実行計画。仕様の正本は `docs/plan.md`、状況は `docs/progress.md`。

## 進め方

- 実装は Sonnet 5.5 のサブエージェントに渡し、こちらはレビューに回る。
- 1 タスク = 1 ブランチ = 1 回の依頼。依頼文には「目的」「触ってよい範囲」「完了条件」を書く(下の各タスク)。
- レビューの手順: diff を読む → `vp run verify` → 画面に関わるなら `vp run test:e2e` → `/code-review` → 指摘を戻す。通ってから main に入れる。
- 触ってはいけないもの: `test/vectors/payload-v1.json`、ペイロード v1 の形式。`src/core/palette-data.ts` は凍結していない(D2)。公開を告知したら ID ごとに中身を凍結し直す。
- core は純粋(DOM・ブラウザ保存を使わない)、UI は `ui-conventions` に従う。

## 前提の確認

- 元資料は「壁打ちの前に実装を増やさない」としている。この計画もそれに従い、**フェーズ 0 は判断の材料づくりだけ**で、アプリの挙動は変えない。
- パレットの凍結記述は D2 の決定に合わせて plan.md と AGENTS.md を書き換え済み(P6)。
- 公開ページは既にある。**1 回でも実際に QR 交換されると、パレットの中身は変えられなくなる**(色が変わる)。パレットを変えるなら、告知より前。

## 瓶とアクリルブロック(実装済み。実機確認が残る)

メインページを「シール帳」と「瓶」で切り替える。瓶の中ではステッカーをシールではなくアクリルブロックとして描き、転がしたり揺らしたりできる。

- **ねらい**: 触って楽しい、人に見せたくなる、という「一瞬」を足す。ペイロード、保存、交換の形式は変えない(同じステッカーの別の見せ方)。
- **作り**: ステッカーの絵を厚みのある半透明の角丸ブロックに載せ、影と反射を描く。物理は 2D の剛体(matter-js や planck など)で、描画は canvas か DOM。端末の傾きは DeviceOrientation で拾う(iOS は許可の確認が必要)。
- **気をつける点**: 数百枚で滑らかに動くか(`e2e/scale.spec.ts` と同じ規模で測る)、モーション軽減の設定では静止した山にする、タッチのドラッグと傾きの両立、アクセシビリティ(読み上げは一覧と同じ名前)。
- **進め方の案**: まず使い捨てのスパイクを 1 本(100 枚と 300 枚での動きと見た目だけを確かめる)。良ければ、ビューの切り替え(`ui/app-state.ts` に画面モード)と設定への保存を本実装にする。

スパイクの結果は `docs/jar-spike.md`、本実装の仕様と数値は `docs/progress.md` の「瓶モード」と README。
